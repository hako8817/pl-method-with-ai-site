# 4장 아웃풋 기준 역설계로 제안서를 푼다

## 1. 이 책의 중심 원리

이 책의 중심 원리는 한 문장으로 정리할 수 있다.

**기획은 순서대로 수행하지만, 설계는 원하는 아웃풋에서 거꾸로 시작한다.**

이 문장을 제안 업무에 적용하면, 제안서를 앞에서부터 쓰는 대신 뒤에서부터 설계하게 된다. 문서를 여는 순서는 RFP에서 시작하지만, 사고를 시작하는 질문은 “최종적으로 어떤 제안 산출물이 나와야 하는가”가 된다.

## 2. 먼저 물어야 할 질문은 아웃풋이다

대부분의 제안 업무는 입력에 끌려간다. 고객이 준 요청서를 읽고, 눈에 띄는 요구사항을 표시하고, 그다음 목차를 짜고, 마지막에 본문을 채운다. 이 순서는 물리적 진행 순서로는 맞지만, 설계 순서로는 약하다.

설계는 반대로 가야 한다.

- 최종 제안서에는 어떤 판단이 들어가야 하는가
- 그 판단을 하려면 어떤 대응 구조가 먼저 있어야 하는가
- 그 대응 구조를 만들려면 어떤 질문과 분류가 먼저 필요하는가
- 그 질문을 만들려면 RFP에서 무엇을 먼저 읽어야 하는가

즉 출력에서 입력을 거꾸로 설계해야 한다.

> **[도식: fig-역설계-원리]** — 아웃풋 기준 역설계 개념도: ① RFP 분석 → ② 요구사항 구조화 → ③ 전략·목차 → ④ 좋은 제안서의 실행 순서(→)와, 설계 사고의 역방향(←)을 함께 표시. 파일: [[figures/fig-역설계-원리.svg]]

## 3. 제안서는 출력 단위로 나눠서 봐야 한다

아웃풋 기준 역설계는 제안서를 한 덩어리 문서로 보지 않게 만든다. 제안서는 여러 출력의 묶음으로 봐야 한다.

예를 들어 제안 업무의 주요 출력은 다음처럼 나눌 수 있다.

- 요구사항 구조화 결과
- 요구사항 대응 메트릭스
- 제안 전략 요약
- 목차와 섹션 구조
- 섹션별 본문 초안
- 제출 직전 체크 결과
- 착수 입력 후보

이렇게 나누면 각 출력마다 필요한 입력이 무엇인지 다시 물을 수 있다. 제안서가 막연한 문서가 아니라, 작은 설계 단위의 집합으로 바뀌는 순간이다.

## 4. 역설계는 입력 부족을 드러낸다

이 방식의 가장 큰 장점은 “무엇이 없는지”가 빨리 보인다는 점이다. 좋은 제안서는 잘 쓰는 사람의 감에서 나오기보다, 입력 부족을 빨리 드러내고 채우는 구조에서 나온다.

예를 들어 다음과 같은 부족이 보이기 시작한다.

- 요구사항은 있는데 평가 기준이 없다
- 범위는 있는데 제외 범위가 없다
- 차별점은 말하지만 근거가 없다
- 목차는 있는데 섹션별 핵심 메시지가 없다
- 본문은 있는데 착수 단계로 넘길 질문이 없다

이 부족을 드러내는 순간 제안서는 훨씬 강해진다. 왜냐하면 그때부터는 글을 쓰는 대신 질문을 설계하게 되기 때문이다.

## 5. AI는 이 구조화 과정에서 가장 강하다

AI는 이 역설계 과정에서 가장 큰 도움을 줄 수 있다. 이유는 분명하다. AI는 긴 입력을 분해하고, 항목을 분류하고, 누락된 질문을 뽑고, 구조 초안을 만드는 데 강하다.

예를 들어 AI는 다음 일을 빠르게 도와줄 수 있다.

- RFP에서 요구사항과 제약 조건 추출
- 필수/선택/가점 항목 분류
- 대응 메트릭스 초안 생성
- 목차 후보와 섹션 메시지 초안 제시
- 본문 초안 작성
- 누락과 모순 점검
- 착수 입력 후보 정리

하지만 AI는 약속의 수준을 대신 판단하지 못한다. 범위를 어디까지 받을지, 어떤 위험을 감수할지, 어떤 표현이 과장인지, 무엇을 최종 승인할지는 사람이 결정해야 한다.

## 6. 이 장의 결론

제안서는 RFP를 읽고 바로 쓰는 문서가 아니다. 원하는 출력이 무엇인지 먼저 정하고, 그 출력이 나오기 위해 필요한 입력을 거꾸로 설계해야 한다. 이것이 이 책이 말하는 아웃풋 기준 역설계이며, 같은 말로 역함수형 기획이다.

이 원리가 잡히면 제안 업무는 훨씬 재현 가능해진다. 그리고 그때 비로소 AI도 정확한 자리에 들어간다.

이 원리를 실제 제안에 적용하는 첫 단계는 제안 요청서를 제대로 읽는 것이다. 어떤 정보를 어떤 관점으로 읽어야 하는지가 5장의 주제다.

## AI 협업 포인트

**이 단계의 핵심:** 역설계 사고를 AI에 적용한다. 최종 산출물을 먼저 나열하고, "이것을 만들려면 무엇이 필요한가"를 AI에 역방향으로 물어 입력 부족을 빠르게 드러낸다.

### 협업 워크플로우

1. 이번 제안에서 나와야 하는 최종 산출물 목록을 사람이 먼저 정리한다
2. 산출물 목록을 AI에 입력하고 각 산출물에 필요한 입력 항목을 역방향으로 요청한다
3. AI가 산출물별 필수 입력과 없을 가능성이 높은 입력을 생성한다
4. 사람이 현재 확보된 입력과 없는 입력을 구분하고 부족한 항목을 확인 계획으로 전환한다
5. 이 부족 목록이 5장(RFP 분석)과 이후 질문 리스트의 출발 기준이 된다

### 프롬프트 예시

```
다음 제안서 산출물을 만들기 위해 어떤 입력이 필요한지 역방향으로 정리해줘.

[산출물 목록]
① 요구사항 대응 메트릭스
② 제안 전략 요약 (핵심 메시지 + 차별화 포인트)
③ 제안서 본문 초안
④ 착수 입력 후보 정리

각 산출물에 대해 표로 정리해줘:
- 반드시 있어야 하는 입력 (없으면 만들 수 없는 것)
- 있으면 유리한 입력 (품질을 높이는 것)
- 지금 빠져 있을 가능성이 높은 입력 후보
```

### 입출력 예시

**입력**
산출물: 요구사항 대응 메트릭스

**AI 출력 초안**

| 입력 항목 | 구분 | 비고 |
|---|---|---|
| RFP 요구사항 전체 목록 | 필수 | 없으면 메트릭스 작성 불가 |
| 평가 항목과 배점 기준 | 필수 | 대응 우선순위 결정에 필요 |
| 우리 조직 대응 가능 범위 | 필수 | 사람이 직접 제공해야 함 |
| 유사 사업 수행 이력 | 있으면 유리 | 근거·증빙 섹션에 연결 가능 |
| 경쟁사 예상 접근 방식 | 있으면 유리 | 차별화 포인트 설계에 활용 |

**사람이 확인할 사항**
- 현재 어떤 입력이 없는지 체크
- 없는 입력이 곧 5장 RFP 분석과 고객 질문 리스트의 기준이 됨

### 사람이 확인해야 하는 판단 체크리스트

- [ ] 이번 제안의 최종 산출물 목록을 사람이 먼저 정의했는가
- [ ] AI가 제시한 필수 입력 중 현재 없는 것을 목록화했는가
- [ ] 없는 입력을 확보하는 방법(RFP 재독, 고객 질의, 내부 확인)을 계획했는가
- [ ] 이 역설계 결과가 5장 RFP 분석의 출발 기준으로 연결되는가
